# Coordinate Cinematic Interactions

Classify the request, select the smallest complete workflow, and preserve the
handoff contract. Do not reproduce specialist procedures here.

## Route once

- Use `$build-interactive-parallax-scenes` when flat artwork must become an
  input-driven multilayer scene with pointer or scroll depth.
- Use `$create-aligned-cinematic-art` for registered themes, lighting variants,
  and paired inactive/active plates.
- Use `$build-layered-aperture-scenes` for exact windows, windshields,
  portholes, arches, and other openings revealing content behind them.
- Use `$render-parallax-transitions` for time-driven encoded parallax reveals
  and lateral camera-motion illusions.
- Use `$render-ambient-cinematic-loops` for periodic environmental motion
  without structural drift.
- Use `$render-hinged-cinematic-transitions` for deterministic rigid doors,
  gates, hatches, panels, and covers.
- Use `$integrate-cinematic-web-media` when approved assets or registered layer
  bundles only need resilient frontend integration.

After selecting a composite workflow, let it coordinate its specialists. Route
directly to a specialist only when the request is genuinely single-stage.

## Preserve the shared contract

Before handoff, lock:

- geometry master, canvas, camera, crop, perspective, and protected pixels
- aperture and mask ownership
- layer and occlusion order
- theme mapping and effect ownership
- output paths, media formats, and validation evidence

Do not let a downstream stage silently change an upstream invariant. Repair the
smallest responsible plate or coherent geometry group when refinement exposes
a defect.

## Coordinate unmatched multi-stage work

When no composite workflow fully covers the request:

1. Inspect the project, approved artwork, active consumers, and constraints.
2. Lock the shared contract.
3. Sequence registered artwork and apertures before motion.
4. Keep parallax, ambient, and mechanical transforms independently owned.
5. Integrate only approved outputs with bounded fallbacks.
6. Verify each handoff and the final consuming experience.

## Finish intentionally

Update consumers atomically. Remove superseded public media, abandoned trials,
verification renders, duplicate versioned outputs, and disposable keyed
intermediates. Retain only active consumer assets plus the approved masters,
masks, registered plates, manifests, render scripts, and keyed sources that are
actually required for deterministic regeneration.
